# 标准校准

“标准校准”是显式触发的、按单个系统执行的结构拆分流程。它只把目标系统在核心四层中已经存在的
内容迁移到四个同径独立文件，不审查、补充或改变系统语义。

## 输入

执行前必须取得以下两个输入：

- 目标系统名称；
- 用户明确指定的共同相对路径 `P`。

若目标系统名称不明确，执行者必须先向用户确认。若用户尚未给出 `P`，执行者必须询问；不得根据
系统名称、现有目录或实现位置自行推断路径。

`P` 不含层根目录和扩展名。它的每个路径分量都必须使用小写 snake_case；不符合要求时必须请用户
重新指定。

## 固定输出

四层目标文件固定为：

```text
spec/charter/P.md
spec/model/P.spec
spec/coding/P.md
impl/arceos_ex/src/P.rs
```

四个文件必须使用完全相同的 `P`，只有层根目录和扩展名不同。

## 拆分规则

执行者只迁移目标系统在 Charter、Model、Coding 和 Impl 中已经存在的内容。迁移不得增加、删除、
修正或重新解释该系统的语义与运行时行为，也不得顺带处理其它系统。为保持规格加载和构建有效，
可以调整拆分直接需要的 include、module declaration、import 和注册引用；这些调整不得形成新的语义、
接口或行为。

若目标文件已经存在，必须把目标系统所属内容合入其中，并保留文件内不属于该系统的既有内容，不得
覆盖整个文件。若任一目标路径已经属于另一个系统，必须停止并请用户重新指定 `P`。

若目标系统在四层中已经分别位于上述同径独立文件，报告无需修改并停止。完成一个系统的拆分和必要
引用调整后也立即停止，不继续处理其它系统或开展其它规格、实现工作。

普通 `charter-first`、Charter 保护锁、验证和提交约束继续由通用 Guidance 与仓库规则负责，本流程
不另行定义这些规则。
