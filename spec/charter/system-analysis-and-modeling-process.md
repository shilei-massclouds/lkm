# 系统分析与建模流程

本项目的所有层级系统，都按照如下顺序进行分析、识别和建模。

## 1. 系统功能

系统作为一个整体对外提供的功能，不考虑内部构成、局部功能和内部交互。

## 2. 系统边界

系统与环境的界面，实际是系统与环境中其它相关系统的界面。

从信号的目标系统的角度分析，分析和确定边界。因为，信号可以从系统内部直接发出，不容易分析信号源系统的边界，但是信号必须首先作用在目标系统的边界上，从目标系统更容易确定边界。

> GAP: 需要明确自发信号和子系统内部信号是否经过当前分析层级的系统边界，避免把目标子系统接口等同于父系统的环境边界。

## 3. 相关系统

环境中与系统存在信号关联的其它系统。

## 4. 信号

三类信号：1）系统能够响应的信号类型；2）系统能够发出的信号类型；3）系统发给自身的信号类型。

> GAP: 三类信号集合存在重叠，系统发给自身的信号同时属于可发送和可响应信号，尚需明确分类维度。

每种信号作用在目标系统的边界上，对应触发目标系统中的一个相应的迁移/动作。

> GAP: Signal 到 Transition/Action 的绑定语法、同步或异步发送以及失败语义尚未在 formal semantics 中闭合。

## 5. 状态机

系统状态包括标准生命周期状态和自身特有状态。需要分析每个状态和迁移过程。

> GAP: “自身特有状态”尚需明确映射为与受控生命周期状态分离的扩展状态，不能形成任意生命周期状态名。

## 6. 动作

系统的动作过程。
