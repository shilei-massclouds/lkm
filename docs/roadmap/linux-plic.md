# Linux PLIC Object 复用历史

> 本文从 `docs/ROADMAP.md` 拆出，只保留专题历史、证据和细节。当前优先级、状态和下一步顺序以 [`../ROADMAP.md`](../ROADMAP.md) 为唯一入口。

## 下一阶段计划：Linux 6.12 PLIC 二进制复用

本节是当前 P0 的执行清单。每完成一项即更新本节状态并做一次提交；实现变更仍遵循先规格/约束、再代码、再验证的顺序。
`make test` 能够通过是判断阶段计划目标达成的重要验收手段。为实现 Linux PLIC object 对齐，当前部分规格、推导、实现和
测试都可以随执行过程调整，但调整必须服务于 Linux 公开接口和二进制复用目标，并在差异分类中记录清楚。

### 已确认原则

1. 条件编译选择的是 provider 文件组和链接对象，而不是在同一组 Rust 源码内部做大量细粒度裁剪。默认 provider 仍为 `native`；启用 Linux 路径时选择 `irq-sifive-plic.o + Linux ABI/adaptor shim`，并排除原生 PLIC 对同一硬件的 claim/complete/source enable 接管。
2. 首轮采用简单直接链接方案：`PLIC_PROVIDER=linux-object` 时直接把 `irq-sifive-plic.o` 作为 linker input 传入。静态库封装暂不作为首轮目标；后续若改为 `.a`，必须通过 `--whole-archive` 确保没有全局入口符号的对象文件也会被拉入最终内核。
3. `arceos_ex` 向 Linux PLIC object 的 RISC-V ABI 对齐。当前 Linux `irq-sifive-plic.o` 为 LP64/soft-float ABI，首轮应优先把 `arceos_ex` 切到 soft-float target，例如 `riscv64imac-unknown-none-elf` 或等价 custom target，而不是要求 Linux 对象适配当前 double-float ABI。
4. 上层机制直接向 Linux 形态收敛。Linux object 可见的 initcall section、platform driver、OF/fwnode、irq_domain、irq_chip、chained handler、per-CPU/cpumask 和 lifecycle callback 以 Linux contract 为准；`arceos_ex` 现有对象作为内部承载或 native provider 实现，不再保留一套厚转换后的私有上接口。
5. 下接口按 `nm -u` 逐符号“埋雷”补齐。函数先提供 ABI 正确的兜底实现，默认 panic/fail；全局变量先提供布局和符号名正确的最小对象。只有启动路径实际踩到且功能闭环必须的依赖，才逐项补真实语义；调试、打印、审计、ratelimit 等非关键能力可简化或标记 deferred。
6. Linux 二进制对象来自与本项目并列的兄弟 Linux tree，默认路径为 `../linux-6.12/`；本项目只在 `impl/providers/linux-6.12.mk` 中维护 provider registry、对象相对路径和必要 ABI/provenance 注释，不在仓库内保存 Linux `.o` 副本。
7. 进入下接口排雷阶段后，以已有原生 PLIC/IRQ/UART 近似等价实现为承载基础，优先做小规模 kernel 对齐和薄 shim 补充。若踩到必须新增正式对象、大功能缺失、或方向策略难以判断的问题，应暂停实现推进，先把问题归类并讨论后再继续。

### 执行清单

1. **已完成：建立 Linux PLIC object 输入基线**。已确认 Linux `drivers/irqchip/irq-sifive-plic.o` 的 ELF header、RISC-V flags、section 列表、defined/local symbols、`nm -u` undefined symbols 和 Linux 构建配置。当前对象为 RISC-V relocatable、RVC、soft-float ABI，无全局 defined symbol，入口依赖 Linux section 和 local symbols；对象来源、ABI、section 和 undefined symbol 分类现在集中记录在 `impl/providers/linux-6.12.mk` 的 provider 注释中。
2. **已完成：建立 provider registry 与兄弟 Linux tree 输入规则**。`impl/providers/linux-6.12.mk` 声明 `linux-object` provider 的 kind、cfg 和对象路径；默认布局为同一父目录下并列的 `linux-6.12/` 与 `lkm/`，对象默认取自 `../linux-6.12/drivers/irqchip/irq-sifive-plic.o`。`arceos_ex` Makefile 只消费 registry 并校验对象存在，不再维护分散的 provider 名单或仓库内对象副本。
3. **已完成：将 `arceos_ex` ABI 切到 Linux 对齐的 soft-float 目标**。默认 RISC-V target 已从 `riscv64gc-unknown-none-elf` 调整到 `riscv64imac-unknown-none-elf`，生成的 native kernel ELF flags 为 `0x1, RVC, soft-float ABI`，与 Linux `irq-sifive-plic.o` 一致。已先不引入 Linux `.o` 验证 native provider：`make -C impl/arceos_ex build APP=smoke TARGET=riscv64imac-unknown-none-elf` 和 `make -C impl/arceos_ex run APP=smoke TARGET=riscv64imac-unknown-none-elf` 通过，smoke 结果为 `passed=36 failed=0 total=36`。
4. **已完成：加入 provider 级条件编译开关**。构建入口已增加 `PLIC_PROVIDER ?= native`，支持 `native` 和 `linux-object`，非法值会直接报错。该开关目前只选择 cfg、构建输出目录后缀和 linker input，默认 native 构建保持通过；`PLIC_PROVIDER=linux-object` 能进入 Linux provider 构建路径。
5. **已完成：首轮直接链接 `irq-sifive-plic.o`**。`PLIC_PROVIDER=linux-object` 时会通过 provider registry 把 `../linux-6.12/drivers/irqchip/irq-sifive-plic.o` 作为 `rustc` linker input 传入，暂不封装静态库。初次验证发现如果不保留 Linux section，linker 会把未引用代码 GC 掉；加入 Linux section `KEEP` 后，失败点已正确推进到 `nm -u` 对应的 undefined symbols，说明对象已被纳入真实链接。
6. **已完成首轮：对齐 Linux linker section 入口**。已在 linker script 生成器中增加 Linux-shaped section ranges，识别并保留 `.init.text`、`.initcall6.init`、`.data..percpu`、`.data..ro_after_init`、`__irqchip_of_table`、`__bug_table` 和 `.alternative`；Rust 侧已增加 Linux initcall6 裸函数指针 range 读取和受控执行器。不要把 `.initcall6.init` 混入现有 Rust `InitcallEntry` section，因为二者 entry 格式不同。当前 `PLIC_PROVIDER=linux-object make run APP=smoke` 已执行到 Linux PLIC initcall，并在 `__platform_driver_register` 兜底 shim 处停下，说明入口链路已贯通到下一层。
7. **已完成首轮：生成下接口 undefined symbol 台账并建立兜底 shim**。已以 `riscv64-linux-gnu-nm -u irq-sifive-plic.o` 为输入建立符号台账，分类覆盖全局变量、普通函数、IRQ core、OF/fwnode、platform driver、memory allocator、per-CPU/cpumask、spinlock、printk/ratelimit、stack protector 等。`objects/linux_plic_shim.rs` 先实现 exact symbol shim：全局变量给最小对象视图，函数默认进入 `linux plic shim trap` fail 边界。`PLIC_PROVIDER=linux-object` 现在能够完成链接，最终 ELF 保留 Linux PLIC local symbols、`.linux_initcall`、`__irqchip_of_table`、`.alternative`、`__bug_table` 和 `.data..percpu`，且无 remaining undefined symbol。
8. **已完成：实现 Linux initcall6 与 platform driver 最小真实路径**。`.initcall6.init` 中的 PLIC driver initcall 已能被执行；`__platform_driver_register` 已从兜底 trap 推进为最小记录语义，会保存 `struct platform_driver` 指针并要求 `.probe` 指针非空。Linux 可见的 `platform_device/device/fwnode` 最小视图已建立，QEMU virt PLIC compatible 可匹配 `plic_driver.driver.of_match_table`，并真实调用 `plic_platform_probe()`；probe 返回值已由 `linux_plic.boundary_facts` checkpoint 约束为 0。
9. **已完成首轮：补齐 `plic_probe()` 必须下接口语义**。已按 probe 实际路径补最小 OF/fwnode 属性读取、资源/ioremap、kmalloc/bitmap 分配、per-CPU/cpumask、hartid/cpuid、spinlock、irq domain instantiate、parent IRQ mapping、chained handler 记录、syscore/cpuhp 记录等受限语义；打印、ratelimit、调试和未进入 runtime 的 IRQ core callback 仍保持 deferred 或兜底 fail。当前验收结果表明 `plic_probe()` 能完成 PLIC 私有状态创建、context 选择、MMIO 映射和后续 IRQ core 注册调用。
10. **已完成第二轮：接入 Linux IRQ domain leaf flow / chained handler runtime 服务面**。`irq_domain_instantiate`、`irq_find_matching_fwspec`、`irq_create_mapping_affinity` 和 `__irq_set_handler` 已记录 domain/chained handler 注册事实；`handle_external_interrupt()` 在 `PLIC_PROVIDER=linux-object` 下进入 Linux `plic_handle_irq` claim loop。runtime 现在不再由 `generic_handle_domain_irq` 直接写 claim register 完成 source，而是按 Linux-shaped leaf flow 推进：首次遇到 hwirq 时调用 Linux `plic_irqdomain_ops.alloc`，由黑盒对象内部执行 `plic_irq_domain_translate -> plic_irqdomain_map -> irq_domain_set_info`，shim 只记录 Linux 对象交出的 `plic_chip`、`handle_fasteoi_irq` 和 leaf `irq_data/irq_desc` 视图；UART source gate 打开也会先确保 leaf mapping 已存在，再调用 Linux `plic_chip.irq_enable(irq_data)`，由黑盒对象打开 context enable bit 和 priority；随后显式执行 Linux PLIC UART chip callback exercise event，在同一 leaf `irq_data` 上调用 `irq_disable -> irq_enable -> irq_mask -> irq_unmask`，并临时设置 `IRQD_IRQ_DISABLED` 调用一次 `irq_eoi` 覆盖 Linux disabled EOI 特殊分支；同一 event 还临时开启 `PLIC_QUIRK_EDGE_INTERRUPT`，调用 Linux `irq_set_type(EDGE_RISING)` 让黑盒对象内联的 `irq_set_chip_handler_name_locked()` 把 leaf 切到 `plic_edge_chip`/`handle_edge_irq`，随后调用 `plic_edge_chip.irq_ack` 覆盖 edge ack 分支，再用 `irq_set_type(LEVEL_HIGH)` 恢复 `plic_chip`/`handle_fasteoi_irq` 和 enabled/unmasked 状态；同一组显式边界还覆盖 valid domain + unmapped hwirq 的失败返回，确认 `generic_handle_domain_irq` 返回 `-EINVAL` 并记录 source/errno，不经过非关键的 ratelimit/打印路径；`linux_plic.boundary_facts` checkpoint 只读观察这些 event 留下的计数事实。之后 `handle_fasteoi_irq` 先恢复 Rust `tp` 分发现有 `IrqHandlerRegistry` action，再切回 Linux `tp` 调用 `plic_chip.irq_eoi(irq_data)`，由 Linux `plic_irq_eoi` 写回 claim register 完成 source。`irq_get_irq_data` 已提供 parent/leaf 最小 `irq_data` 视图，`cpuhp_setup_state` 已按 `invoke=true` 调用 boot CPU startup，并通过 `irq_get_trigger_type(parent_irq) -> enable_percpu_irq(parent_irq, type)` 的 Linux 数据面记录 parent IRQ gate；真实 root external input gate 仍由现有 `InterruptStream` 控制。parent chained handler desc/chip 已记录 `chained_irq_exit` 触发的 parent EOI 事实，并保存 chained handler 声明的 `IRQ_NOREQUEST/IRQ_NOPROBE/IRQ_NOTHREAD` status；leaf map 阶段的 `irq_set_noprobe()` 已通过 `irq_modify_status()` 写入 UART leaf desc status 并由 checkpoint 约束。更完整 generic IRQ core 语义仍待后续排雷。`tp/thread_info` 边界已按 Linux object 运行期视图处理：进入 Linux object 前切到 Linux `thread_info`，返回 Rust dispatch 前恢复 Rust `tp`，Linux `tp` 激活期间关闭本地 SIE，避免嵌套中断把 Linux `tp` 泄漏到 Rust 执行上下文。
11. **已完成当前轮：让 native PLIC provider 收敛到同一上层 contract**。已建立薄 `objects::plic_provider` contract，把 provider 后端 setup、domain translate/map/resolve、运行期 source gate enable、external interrupt handling、UART leaf chip callback exercise、unmapped IRQ fail boundary exercise，以及 claim/dispatch/complete/zero-claim/loop-exit 观测计数收口到同一组 provider API；native provider 通过 Rust `Plic`/`PlicIrqDomain` 内部实现提供这些服务，Linux object provider 通过 `irq-sifive-plic.o` 和 shim 提供同名服务。上层 `InitcallPhase`、`PlicIrqDomain`、root external IRQ entry、`IrqDispatchTree`、`IrqHandlerRegistry`、serial8250 console TX 等使用者不再直接选择 native/Linux 分支。chip callback 与 unmapped fail 已从混合 boundary exercise 拆为两个独立 provider event；当前轮还补齐 parent IRQ startup/chained EOI/status 和 leaf `IRQ_NOPROBE` 的最小 generic-core 事实，条件编译切换已经收敛为链接输入和 provider 文件组选择。
12. **已完成当前轮：建立分层验证闭环**。link-only、initcall 注册、platform match/probe、domain/chained 注册、leaf IRQ flow、chip callback、unmapped fail、parent/chained IRQ、desc status 和 UART interrupt cycle 已有 checkpoint/KUnit/smoke 观察点，其中 `linux_plic.boundary_facts` 只读验证黑盒边界流程、交换数据以及 chip callback exercise event 留下的 `irq_enable/irq_disable/irq_mask/irq_unmask/disabled_irq_eoi/edge_irq_ack` callback 计数，并确认 edge 分支通过 Linux object 自身的 `irq_set_type` 切换到 `plic_edge_chip` 后再恢复 level/fasteoi；同一 checkpoint 还验证 unmapped hwirq fail boundary 的 `-EINVAL` 返回、source/errno 记录、parent IRQ gate/status、leaf `IRQ_NOPROBE` 和 exercise success。`uart_irq_chain.observer_real_path` 已在 Linux PLIC object provider 下观察到 claim/dispatch/complete 计数闭合、zero-claim/loop-exit 成对闭合。checkpoint/KUnit handler 已收口为只读 observer，不再注册 app smoke 或 mutating allocator/vmalloc/ioremap action。当前验收命令 `make test` 已通过，summary 为 `overall total=49 pass=49 fail=0`，其中 spec verify `1/1`、KUnit checkpoints `11/11`、app smoke `37/37`。
13. **已完成当前轮：同步规格与差异分类**。`spec/charter/main.md` 和本 roadmap 已记录当前阶段的已覆盖边界与显式 deferred 范围。已覆盖范围包括 initcall/platform/probe、domain/chained 注册、leaf mapping、UART IRQ runtime、chip callback exercise、unmapped fail、parent startup/chained EOI/status、leaf `IRQ_NOPROBE`、UART leaf action/depth 的最小 Linux-like 数据面、`request_irq` 成功路径到 provider action request 事实的最小对齐，以及 request action-chain view、真实 Linux `irq_desc.action` 偏移写入、`irq_desc.status_use_accessors` 与 `irq_common_data.state_use_accessors` 分离读写和 runtime leaf dispatch 的匹配；显式 deferred 包括 ratelimit/打印提示、完整 root INTC irqchip、完整 irqdesc/free/threaded 生命周期、CPU hotplug/offline、SMP affinity、suspend/resume 和真实 edge 平台 runtime。后续每完成一层仍需继续更新差异分类，未分类前不直接把 workaround 落入主体实现。
14. **已完成收尾：冻结 Linux PLIC object 首轮闭环基线**。PLIC 首轮二进制复用到此收尾，不再为了“补齐完整 Linux generic IRQ core”而主动深挖 free/threaded、完整 irqdesc lifecycle、root INTC irqchip、SMP affinity、CPU hotplug/offline、suspend/resume 或真实 edge runtime。上述项保留为显式 deferred；只有后续新目标实际踩到这些路径，或验证发现当前闭环不足以支撑 provider 互换时，才按“踩雷/排雷”方式补最小正式语义。若排雷过程暴露必须新增大对象、大功能缺失或方向策略不清，应先停下归类并讨论。

### 当前进度与后续计划

当前已完成 `irq-sifive-plic.o` 的输入基线、兄弟 Linux tree provider registry、soft-float ABI 对齐、provider 级条件编译、直接链接、Linux section `KEEP`、undefined symbol exact shim、initcall6 执行、platform driver 注册、compatible match、`plic_platform_probe()` 真实调用，probe 到 domain/chained handler 注册的黑盒边界事实观测，Linux PLIC object provider 下的 UART interrupt cycle runtime 闭合，UART leaf `plic_chip` 的 `irq_enable/irq_disable/irq_mask/irq_unmask/disabled_irq_eoi`、synthetic edge `plic_edge_chip.irq_ack` 以及 unmapped IRQ fail boundary 显式 event exercise。provider 后端 setup、domain translate/map/resolve、运行期 PLIC source gate、external interrupt handling、UART leaf chip callback exercise、unmapped IRQ fail boundary exercise 和计数观测已经收敛到薄 `objects::plic_provider` contract，native 和 linux-object provider 共享同一上层调用入口；parent IRQ startup/chained EOI/status、leaf `IRQ_NOPROBE`、UART leaf action/depth，以及 `request_irq -> provider action request -> action-chain view -> irq_desc.action -> desc status/common state/depth readback -> runtime action match` 的最小 generic-core 事实也已纳入 checkpoint 约束。当前 `make test` 已覆盖 native 与 linux-object provider 矩阵；其中 checkpoint/KUnit handler 已收口为只读 observer，app smoke 独立覆盖 payload 运行期行为。当前阶段已经作为 Linux PLIC object 首轮二进制复用验证闭环收尾，但仍不是完整 Linux generic IRQ core 复用：真实 runtime 主线仍是 QEMU/SiFive 无 edge quirk 的 level IRQ，更完整 root INTC、irqdesc lifecycle、CPU hotplug/SMP affinity/suspend 和真实 edge 平台 runtime 保留为后续按需排雷项。

PLIC 收尾后的后续策略：

1. 不再主动深挖 PLIC/generic IRQ core 的 deferred 项。free/threaded、完整 `irq_desc/irq_common_data` 状态迁移、root INTC irqchip、parent entry mask/ack、CPU hotplug/offline、SMP affinity、suspend/resume 和真实 edge 平台 runtime 仅在后续目标实际踩到时补最小正式语义。
2. 继续保持非关键能力 deferred：ratelimit/打印提示可继续简化，除非它们成为定位新问题的必要证据。
3. 后续若重新进入 PLIC 排雷，仍以 checkpoint/KUnit/smoke 和 `make test` 作为阶段验收；若出现必须新增正式对象、大功能缺失或方向策略难以判断的问题，先归类并讨论，再进入实现。
4. PLIC 基线冻结后，后续工作重心优先转向 nightly/压力复现与纵向差分；若新证据显示必须回到 PLIC/generic IRQ core 排雷，再按最小正式语义补齐。每次切换目标前仍需同步 `spec/charter/main.md`、必要 coding/model 规格和本 roadmap。
