# Roadmap

本文是项目唯一的优先级和任务状态入口。其它文档可以保留设计背景、约束、命令和专题方案，但不再维护独立的 P0/P1/P2 计划表。

已确认但尚未闭环的实现缺陷记录在 [`docs/DEFECTS.md`](DEFECTS.md)，不与规划性任务混写。

## 优先级规则

- `P0`：当前最应优先推进，直接影响日常审阅或当前闭环质量。
- `P1`：近期应推进，通常依赖 `P0` 的结果或与其紧密相邻。
- `P2`：后续扩展项，应在当前闭环稳定后推进。

## 当前焦点

1. P0 仍按证据驱动：缺陷复现、stress 回归、checkpoint/KUnit/smoke 和必要 objdump/trace 先定位边界，再改规格和实现；不得通过更换输入形态或新增一次性测试 API 盲试。
2. `/bin/sh -> /bin/ls` 当前已越过 clone/wait4/execve 主线并纳入默认 `make test` 发行版 shell 外部命令门禁；成功 marker 是 `lost+found` 与 `user exit status=0`，详细 fork/wait/exec facts 由 checkpoint/KUnit 覆盖。
3. 当前下一步切到 Linux runtime checkpoint v2：以 `/home/cloud/gitLKM/linux-6.12` 的 `lkm/checkpoint-markers` 为插桩基线，不另开分支，优先覆盖 instrumentation plan 中 103 个 exact-mapped checkpoint。`range` 与 `unmapped` 继续作为后续 mapping 任务；paired diff 只比较每个 case 显式声明的顺序兼容交集，scope 外事件进入报告但不直接判失败。
4. 目录操作 smoke、原生 `/sbin/init` / OpenRC 诊断和 Linux-aligned 用户 trap 栈与 VMAP guard 仍保留为后续 P0/P1 任务；guard 用于越界保护/诊断，不替代把 exec/mm 等大对象移出内核栈。
5. PLIC/UART/serial、virtio/block/ext2、启动阶段审计、用户态 payload 和历史交接细节已拆入 `docs/roadmap/*.md`。主 roadmap 只维护当前状态、统一计划和入口链接。
